# GitHub: відтворення лабораторної роботи 2

Інструкція для OrderFlow 1.1, варіант 2. На момент підготовки remote GitHub не налаштований: коміти та CI прогнані локально, issues і віддалені Actions ще не існують. Не записуйте локальні результати як GitHub run.

## 1. Передумови і локальна перевірка

Потрібні Git, .NET SDK 10.x, GitHub-акаунт з правом створити репозиторій. Для браузерних доказів — Playwright MCP.

У PowerShell:

```powershell
cd D:\lab2
dotnet --version
$env:ORDERFLOW_VARIANT = "2"
dotnet restore
dotnet build
dotnet test
```

Запустити застосунок в окремому PowerShell:

```powershell
cd D:\lab2
$env:ORDERFLOW_VARIANT = "2"
dotnet run --project src/OrderFlow.Api
```

Відкрити http://localhost:5000 (Swagger: /swagger). Демооблікові записи наведені в README.md. Не запускати другу копію сервера на цьому ж порту.

## 2. Створити репозиторій і під'єднати remote

1. GitHub → **New repository**, ім'я `orderflow-lab2`, Public/Private — як вимагає курс.
2. Створити порожнім: без README, license і .gitignore, щоб не створювати сторонній початковий commit.
3. Переконатися, що **Settings → General → Features → Issues** увімкнено; дозволити GitHub Actions у **Settings → Actions → General**.
4. Скопіювати URL і виконати (замінити USERNAME):

```powershell
cd D:\lab2
git remote add origin https://github.com/USERNAME/orderflow-lab2.git
git remote -v
```

Якщо origin уже існує, перевірити `git remote get-url origin), за потреби змінити через `git remote set-url origin <URL>`.

## 3. Послідовно надіслати коміти для окремих Actions runs

Workflow: `.github/workflows/ci.yml`. Надсилати коміти саме послідовно, кожного разу просуваючи main уперед. Після кожної команди перевірити вкладку **Actions**:

```powershell
# Початковий стан репозиторію
git push -u origin 6ed8cfc153b3e59faff555fd11fa969fbc71bfe6:refs/heads/main

# Workflow із restore/build/test — базовий успішний прогін
git push origin 52f7c7c84a6b92b7a143b31c8bd902dc9af27a92:refs/heads/main

# Експеримент зі ставкою знижки (очікуються 5 успішних тестів)
git push origin 97490f1bba6b89d05735480bd23aac6c311d1b36:refs/heads/main

# Експеримент із маршрутом: очікується 1 падіння тесту з 404 замість 200
git push origin e0e2e58f1d7e766e4e5bab150e5f5b238678b401:refs/heads/main

# Відкати маршруту й знижки: фінальний успішний прогін
git push origin df6ebed0cf14ca03e9458047dbfd57bcd98048d0:refs/heads/main
```

Очікувана хронологія: 6ed8cfc — початковий workflow trigger; 52f7c7c — CI доданий, 5 тестів проходять; 97490f1 — 5 проходять; e0e2e58 — `Application_starts_and_lists_products` отримує 404 замість очікуваного 200 (4 passed, 1 failed); df6ebed — build успішний, 0 warnings/errors, 5 тестів проходять. Не використовуйте `--force). Якщо перший push відхилений через README/початковий commit, створіть порожній репозиторій, аби зберегти fast-forward послідовність.

Збережіть URL базового CI, обох експериментів і фінального відкату, їхні статуси та screenshot кроку помилки на GitHub. Якщо початковий workflow має окремий run, зафіксуйте і його. Потім виконайте локально:

```powershell
git checkout main
git status --short --branch
dotnet restore
dotnet build
dotnet test
```

## 4. Додати звіт і локальні докази

Після п'яти історичних push-ів додати лабораторні артефакти окремим commit, щоб послідовність CI вище лишилась відтворюваною:

```powershell
git add artifacts lab2.docx гітхаб.md план.md
git status --short
git commit -m "docs: add lab 2 report and evidence"
git push origin main
```

Перевірити staging: не додавати тимчасові файли Word `~$*.docx), кеші або локальну базу. В `artifacts/` лежать `investigation-note.md), чотири чернетки у `issues/`, три screenshots (Support, order, invoice), JSON-докази API і `ci-local-runs.md`.

## 5. Опублікувати чотири Issues

Відкрити **Issues → New issue**. Перенести заголовок і весь опис зі відповідного UTF-8 файла, додати PNG-доказ перетягуванням у поле issue або посиланням на файл в main, поставити labels `bug) та P1/P2/P3, надіслати й записати номер і URL. Не створювати дублікат, якщо відповідна issue вже існує: знайти її та додати відсутній доказ/коментар.
